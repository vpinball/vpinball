# Scripting interface glue (IDL)

On Windows, the scripting interface described in `src/core/vpinball.idl` is exposed to VBScript through COM and a registered Type Library. All other builds (macOS, Linux, iOS, Android, Windows MinGW) use the Wine VBScript engine without a Type Library, so the interface glue is generated ahead of time and committed to `src/core/generated/`:

| File | Generated by | Contents |
|---|---|---|
| `vpinball_standalone_i.h`, `vpinball_standalone_i.c` | `widlgen.sh` (Wine `widl`) | Interface declarations and GUIDs |
| `vpinball_standalone_i_proxy.cpp` | `genproxy.sh` (Java parser in `parser/`) | `IDispatch::GetIDsOfNames` and `IDispatch::Invoke` implementations |

Regenerate both whenever `src/core/vpinball.idl` changes.

## Interface files

Requires a built Wine source checkout (for `tools/widl/widl` and `include/`). By default the script looks for it in a `wine` folder next to the repository; set `WINE_PATH` to use another location:

```
WINE_PATH=/path/to/wine ./tools/idl/widlgen.sh
```

## Proxy stub

Requires a JDK and Gradle:

```
./tools/idl/genproxy.sh
```

The parser reverse-engineers the name-to-DISPID mappings and invocation logic that a Type Library would normally provide. It was developed through trial and error, so review the generated diff carefully.
